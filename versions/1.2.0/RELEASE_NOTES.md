# 1.2.0 — 2026-10-30

> 正文抓取从「一篇一篇顺着等」改成「五路并发竞速，谁先给出可用正文就用谁」。

## 新增

- **并发竞速抓正文**：一次取 5 个候选，每个一个后台线程同时发请求，主线程按完成顺序收结果，
  第一个能切成练习段的立即采用，不等其余请求。
- **1 小时预取缓存**：落选但抓成功的文章写进独立表 `prefetch_cache`，下次换文章先查它，命中即 0 网络。
- **feed 提前开跑**：凑够 3 个源就开拉正文，不等最慢的源（总预算 24 秒）。
- 正文请求加全局并发上限 12，连点「换一篇」也不会把连接数打爆。

## 改进

- 冷启动 **6.7 秒 → 2.3–2.8 秒**；之后连续换 3 篇均 0.00 秒。
- 每次竞速稳定落 5 篇进预取缓存；预取表独立，清理时不会误伤词典/译文缓存与练习记录。
- 全失败或超时会退回离线示例，不会一直转圈。

## 修复

- 落选文章曾被误记进「已看过」集合，导致预取缓存永远命中不了 —— 拆成「已展示」与「抓取失败」两个集合。

## 测试

169 个单元测试（新增竞速服务 12 项 + 预取表 6 项）、GUI 冒烟 29 项；exe 13.1 MB 重打包。
