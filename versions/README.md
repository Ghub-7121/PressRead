# 历代版本归档

本目录按版本号存放 PressRead 的发布记录与成品，一个版本一个文件夹。

## 目录约定

```
versions/
└── <版本号>/
    ├── RELEASE_NOTES.md        该版本的更新说明（发布时写定，事后不改）
    └── PressRead-<版本号>.exe   该版本的可执行成品（有归档才放）
```

## 编号规则

| 位 | 含义 | 判定 |
| --- | --- | --- |
| 第一位（主版本） | 整体重写、数据结构不兼容 | 需要迁移或重做界面 |
| 第二位（次版本） | **新增用户能感知的功能** | 多一个按钮、多一类来源、换一条链路 |
| 第三位（修订号） | 修 bug、调文案、改兼容性 | 不新增功能，只让已有的更稳 |

- 一次发布只做一件事就升次版本；同一批里混进来的零散修复，若能单独说清，补一个修订号。
- **带 † 的版本是「回溯补记」**：改动本来混在同一次构建里、没有单独打过包，为了让改动可追溯才补一个修订号。这类条目只有发布记录，没有独立成品。

## 成品归档现状

- **1.0.0 – 1.6.0 没有保留 exe**：当时每次重新打包都直接覆盖 `dist/PressRead.exe`，历史构建没有另存。
  源码随仓库演进，按需可从 `CHANGELOG.md` 的改动清单重建对应版本，但已无原始二进制可比对。
- **1.7.0 已归档**：`1.7.0/PressRead-1.7.0.exe`（13.2 MB，`--smoke` PASS）。
- **从 1.8.0 起**：每发一版，把当次 exe 复制进对应文件夹，同时在 GitHub Releases 附一份；
  `.gitignore` 已排除 `versions/**/*.exe`，仓库本身不背二进制，成品走 Releases。

## 关于「改了但没升版本号」

1.6.0 这一批里有两处修复是顺手做掉的，发布时没有单独编号，现补记为 **1.6.1†**（RSS 裸 `&` 解析失败）
与 **1.6.2†**（`--selftest` 正文抽取报错）。其余版本里发现的同类问题都在打包前修完并计入该版本，
不再单列，避免把一次构建拆成好几个假版本。
